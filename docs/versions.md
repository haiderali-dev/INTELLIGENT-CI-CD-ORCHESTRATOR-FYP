# Versions

Every pinned version, with the official source it was checked against. Rule 1.4: a version is pinned
only after checking its official source, never from memory.

From Phase 8 onward this file is regenerated by `python scripts/report/versions.py`, which reads
`plugin/pom.xml`, `jenkins/controller/plugins.txt`, `backend/pyproject.toml` and
`frontend/package.json`. Until then it is maintained by hand, and every row carries the date it was
checked.

**One transitive pin breaks the seven-day cooldown, as a security fix (D-071).** `certifi`, which
`httpx` brings in, is locked at 2026.10.19, published on 2026-10-19, three days before it was taken.
The version it replaced, 2026.7.22, trusts a CA root under which eight intermediates have compromised
keys (PYSEC-2026-4320, GHSA-6q48-6c7w-9gw2). `pip-audit` 2.10.1 found that vulnerability among the
49 packages the backend image installs, and found none after the change. In place of the
cooldown, the new wheel was compared file by file with the locked one: the code is unchanged but for
its version string, and the CA bundle differs only by the removal of `emSign ECC Root CA - G3`.
The lock was written by the project's own uv, 0.12.20 in `.venv-tools/`, the same version the
backend image uses.

Three pins are deliberately behind the newest release:
- **TypeScript 5.9.3, not 7.0.2.** `typescript-eslint` 8.71 accepts `>=4.8.4 <6.1.0` and
  `openapi-typescript` 7.13 accepts `^5.x`. TypeScript 7 is the native port, and neither tool
  supports it yet. 5.9.3 is the newest release both accept.
- **jsdom 29.1.1, not 30.1.2.** jsdom 30 requires Node `^24.15.0` on the 24 line, and this machine
  runs 24.12.0. 29.1.1 accepts `>=24.0.0`.
- **`@types/node` 24, not 26,** because the frontend is built and tested on Node 24.

The three form packages were read from the npm registry on 2026-10-15 under the same seven-day
cooldown. It skipped `react-hook-form` 7.90.0 (4 days old) and `zod` 4.6.6 and 4.6.7 (4 and 3
days old). Their peer ranges fit: `@hookform/resolvers` 5.9.1 wants `react-hook-form` `^7.55.0`
and accepts `zod` `^3.25.0 || ^4.0.0`, and its other peers are optional, so none was installed.
`zod` was already in the tree at 4.6.7, through `eslint-plugin-react-hooks`, whose range 4.6.5
also satisfies. npm now resolves one copy at 4.6.5 for both. `npm audit --omit=dev` found no
vulnerabilities.

The ten CodeMirror packages were read from the npm registry on 2026-10-15. Each one's newest
release was already past the seven-day cutoff of 2026-10-08, the most recent being `/view`,
`/language` and `/legacy-modes` from 2026-10-07. npm resolves a single copy of `/state`, `/view`,
`/language` and `@lezer/highlight` across all of them. `/lang-xml` brings `@codemirror/autocomplete`
6.20.3 in as its own dependency. `npm audit --omit=dev` found no vulnerabilities.

**`vite` moved from 8.3.2 to 8.3.4 on 2026-10-22 (D-075).**
- **Why:** the testing chapter's evidence campaign ran `npm audit`, and it reported one high
  vulnerability, `vite` 8.3.0 to 8.3.2. That is six advisories against Vite's development server,
  among them command execution through its editor launcher on Windows (GHSA-r825-w8mm-5pxw) and
  cross-origin script execution (GHSA-9jrq-w75r-8gcw).
- **Exposure:** the production frontend is static files from `vite build`, served by nginx, so it
  was not exposed; the development server and the tools that run it were.
- **Why 8.3.4:** npm's suggested fix was 8.3.5, published on 2026-10-21, inside the seven-day
  cooldown. 8.3.4 (2026-10-08) is outside the vulnerable range and is the newest release the
  cooldown allows.
- **The change:** the lock changed only Vite's entry.
- **After it:** `npm audit` found 0 vulnerabilities.
